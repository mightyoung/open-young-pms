# 菜单设计最佳实践指南

> 基于 Ant Design、Atlassian、Figma 等设计系统总结

## 1. 分组原则

### 分组数量
- **推荐：5-7 个分组**
- 超过 7 个分组会增加认知负担
- 不足 3 个分组则分类不够精细

### 每组菜单项数量
- **推荐：≤7 个菜单项**
- 超过 7 个考虑拆分为多个分组
- 少于 3 个考虑合并到其他组

### 分组方式
```
✅ 按工作流程分：工作台 → 项目 → 报告 → 审批
✅ 按角色分：个人工具 / 团队协作 / 管理配置
✅ 按优先级分：常用 / 偶用 / 管理
❌ 避免：按功能类型机械分类
```

## 2. 层级设计

### 层级深度
| 层级 | 适用场景 | 建议 |
|------|----------|------|
| 1层 | 极简应用（≤10项） | 仅顶级菜单 |
| 2层 | 大多数企业应用 ✅ | 顶+子菜单 |
| 3层 | 复杂系统（>50项） | 仅特殊情况 |

### 扁平化原则
```
❌ 深层嵌套
   工作台 > 项目 > 风险管理 > 风险识别 > 风险详情

✅ 扁平结构
   工作台 > 项目 > 风险识别（直接在项目下）
   或者用 Dashboard/快捷方式暴露常用项
```

## 3. 菜单项设计

### 命名规范
- **清晰无歧义**：用"项目列表"而非"列表"
- **动宾结构**：用"创建项目"而非"新建"
- **一致性**：同为动词或同为名词

### 图标使用
```
✅ 保持图标风格一致（线性/填充）
✅ 图标语义与文字匹配
✅ 主色调统一
❌ 图标过多（每项都加图标反而混乱）
❌ 图标语义不清
```

### 状态标识
```
Badge：数量标记（待审批 5）
Tag：状态标记（新/热）
Color：类型区分
```

## 4. 快捷操作

### 全局搜索
- 位置：顶栏或侧边栏顶部
- 功能：模糊搜索菜单/内容
- 快捷键：Cmd/Ctrl + K

### 常用功能置顶
```
├── 最近访问（动态）
├── 收藏夹（用户自定义）
└── 固定入口（系统预设）
```

## 5. PMS 系统菜单优化

### 优化前问题
- 分组过多（11 个分组）
- 层级过深（随手拍下有 5 个子项）
- 功能分散（论坛详情暴露在顶层）

### 优化后结构

```
默认主菜单
├── 仪表盘
├── 项目管理
├── 任务管理
├── 随手拍/隐患
├── 报告中心
├── 审批中心
└── 系统管理

项目详情二级能力
├── 项目流程模板
├── 合同
├── 风险
├── 质量
├── 资源
└── 归档

隐藏/实验能力
├── 论坛（仅保留直达或后续项目讨论化）
├── AI 助手（实验）
├── 草稿箱（并入表单内部）
├── 通知设置（顶栏/个人入口）
└── 数据治理/知识库（平台化专项）
```

### 关键改动
1. **收敛**：默认主菜单固定为项目交付闭环 7 项。
2. **合并**：合同、风险、质量、资源沉入项目详情，不再顶级并列。
3. **隐藏**：论坛、AI、数据治理、知识库不进入默认业务菜单。
4. **分级**：路由元信息使用 `visibility` 与 `section` 区分主线、二级、隐藏和实验能力。
