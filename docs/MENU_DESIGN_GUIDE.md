# 菜单设计最佳实践指南

> 基于 Ant Design、Atlassian、Figma 等设计系统总结

## 1. 分组原则

### 分组数量
- **推荐：5-7 个分组**
- 超过 7 个分组会增加认知负担
- 不足 3 个分组则分类不够精细

### 每组菜单项数量
- **推荐：≤7 个菜单项**
- 超过 7 个考虑拆分为多个分组
- 少于 3 个考虑合并到其他组

### 分组方式
```
✅ 按工作流程分：工作台 → 项目 → 报告 → 审批
✅ 按角色分：个人工具 / 团队协作 / 管理配置
✅ 按优先级分：常用 / 偶用 / 管理
❌ 避免：按功能类型机械分类
```

## 2. 层级设计

### 层级深度
| 层级 | 适用场景 | 建议 |
|------|----------|------|
| 1层 | 极简应用（≤10项） | 仅顶级菜单 |
| 2层 | 大多数企业应用 ✅ | 顶+子菜单 |
| 3层 | 复杂系统（>50项） | 仅特殊情况 |

### 扁平化原则
```
❌ 深层嵌套
   工作台 > 项目 > 风险管理 > 风险识别 > 风险详情

✅ 扁平结构
   工作台 > 项目 > 风险识别（直接在项目下）
   或者用 Dashboard/快捷方式暴露常用项
```

## 3. 菜单项设计

### 命名规范
- **清晰无歧义**：用"项目列表"而非"列表"
- **动宾结构**：用"创建项目"而非"新建"
- **一致性**：同为动词或同为名词

### 图标使用
```
✅ 保持图标风格一致（线性/填充）
✅ 图标语义与文字匹配
✅ 主色调统一
❌ 图标过多（每项都加图标反而混乱）
❌ 图标语义不清
```

### 状态标识
```
Badge：数量标记（待审批 5）
Tag：状态标记（新/热）
Color：类型区分
```

## 4. 快捷操作

### 全局搜索
- 位置：顶栏或侧边栏顶部
- 功能：模糊搜索菜单/内容
- 快捷键：Cmd/Ctrl + K

### 常用功能置顶
```
├── 最近访问（动态）
├── 收藏夹（用户自定义）
└── 固定入口（系统预设）
```

## 5. PMS 系统菜单优化

### 优化前问题
- 分组过多（11 个分组）
- 层级过深（随手拍下有 5 个子项）
- 功能分散（论坛详情暴露在顶层）

### 优化后结构

```
核心入口
├── 仪表盘
└── 看板

驾驶舱（高层专用）
├── 司令舱
├── 指挥台
└── 作战台

项目管理
├── 项目列表
├── 随手拍 ⚡
└── 甘特图

工作流
├── 填写报告
├── 报告中心
└── 审批中心 ⚡

智能
├── AI 助手 🆕
├── 文档中心
└── 知识库

系统配置
├── 用户管理
├── 组织管理
├── 质量管理
├── 合同管理
├── 预算管理
├── 资源管理
├── 数据治理
└── 审计日志
```

### 关键改动
1. **合并**：隐患上报/管理/规则 → 随手拍
2. **提升**：AI 助手独立分组，突出智能化定位
3. **精简**：移除 forum-detail 等冗余项
4. **分组**：按工作流重组，而非按模块
